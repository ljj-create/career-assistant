# career-assistant · Phase 1

> 浏览器操作技术验证模块。通过 Chrome DevTools Protocol（CDP）连接**用户已登录的 Chrome 实例**，读取招聘网站的表单结构，并向指定输入框写入测试内容以验证链路可行性。

本仓库为「AI 求职助手」项目的 **Phase 1（技术验证）** 交付物。Phase 2 将在此结论之上开发可安装的 Chrome 插件。

当前状态：**功能 A / B / C / D 均已在真实招聘网站上验证通过**。

## 项目定位与范围

### 本阶段的目标

验证一条技术链路：**连接浏览器 → 读取网页 → 定位输入框 → 填写内容 → 回读验证**。

### 本阶段明确不做的事

| 不做 | 说明 |
|---|---|
| Chrome 插件 | 属于 Phase 2。本阶段产出的是命令行程序 |
| 用户账号系统 | — |
| 大模型 / Agent | 字段匹配完全基于本地规则 |
| 自动填写完整简历 | 本阶段仅验证单个文本输入框 |
| 自动提交申请 | 任何情况下都不触发提交动作 |
| 兼容全部招聘网站 | 仅针对有限样本站点验证 |
| 读取浏览器 Cookie 文件 | 通过 CDP 操作页面，不接触本地凭据文件 |

### 与常规 Playwright 脚本的区别

| | 常规脚本 | 本程序 |
|---|---|---|
| 浏览器获取方式 | `chromium.launch()` 启动新实例 | `connectOverCDP()` 接管既有实例 |
| 登录态 | 无 | 保留用户在目标站点上的登录态 |
| 生命周期 | `browser.close()` 关闭自身启动的实例 | **从不调用 `close()`**——CDP 模式下该操作会关闭用户浏览器 |

## 目录结构

```
career-assistant/
├── src/
│   ├── types.ts             # 全局数据类型定义
│   ├── connect-browser.ts   # 功能 A：CDP 连接、标签页选取；功能 D：错误表示与输出
│   ├── observe-page.ts      # 功能 B：表单扫描与标签推断
│   └── fill-field.ts        # 功能 C：字段匹配、写入与回读验证
├── package.json
├── tsconfig.json
├── README.md
└── .gitignore
```

模块划分遵循两条原则：

- **浏览器侧逻辑与驱动逻辑分离**：`readFieldsInDom()` 为纯 DOM 实现，不依赖 Playwright，可整体迁移至 Phase 2 的 content script。
- **错误处理集中**：所有用户可见的错误均通过 `AppError` + `reportError` 输出，保证每条错误路径都附带处置建议。

## 使用方法

### 启动测试 Chrome

```powershell
& "$env:LOCALAPPDATA\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="$env:USERPROFILE\chrome-cdp-profile"
```

必须使用独立的用户数据目录：

- Chrome 136 起禁止对默认用户数据目录开启远程调试；
- 同一用户数据目录仅允许一个 Chrome 实例。

可通过访问 `http://127.0.0.1:9222/json/version` 确认端口已生效（应返回 JSON）。

### 在浏览器中完成登录

在**上一步启动的那个 Chrome** 中登录目标招聘网站，并进入表单页面。

### 执行命令

```powershell
npm run connect      # 功能 A：列出候选标签页，输出当前页网址与标题
npm run observe      # 功能 B：读取当前页全部表单控件
npm run fill         # 功能 C：定位姓名字段，写入测试内容并回读验证
npm run typecheck    # 类型检查
```

### 指定标签页

未指定序号时，程序默认选取「最后一个非空白页」，该页面未必是目标表单页。建议先查看候选列表再按序号指定：

```powershell
npm run connect        # 查看候选列表，确认表单页序号
npm run observe -- 2   # 替换为实际序号
npm run fill -- 2
```

> **注意**：序号基于本程序的候选列表，会随标签页的增删而变化，每次运行前应重新确认。

## 输出说明

### 字段类型（`kind`）

| 类型 | 说明 | 可否直接写入 |
|---|---|---|
| `text` | 单行文本框（`text` / `tel` / `email` / `search` / `number`） | 可 |
| `textarea` | 多行文本框 | 可 |
| `select` | 原生下拉选择框 | 需点选 |
| `combobox` | 自定义下拉、日期选择器等复合控件 | 需点选，直接写入未必生效 |
| `checkbox` / `radio` | 复选框 / 单选按钮 | 需点选 |
| `file` | 附件上传 | 否 |
| `hidden` | 隐藏字段 | 否 |
| `password` / `button` | 密码框 / 按钮 | 否 |
| `other` | 未归类 | 否 |

### 标签来源（`labelSource`）

按可信度由高到低排列，用于标签识别有误时定位失效环节：

| 来源 | 含义 | 可信度 |
|---|---|---|
| `aria` | `aria-label` / `aria-labelledby` | 高 |
| `label-for` | `<label for>` 显式关联 | 高 |
| `label-wrap` | 被 `<label>` 整体包裹 | 高 |
| `nearby` | 由容器结构推断 | 中 |
| `placeholder` | 回退至 `placeholder` 属性 | 低 |
| `name` | 回退至 `name` / `id` 属性 | 低 |
| `none` | 未识别 | — |

来源为 `placeholder`、`name` 或 `none` 时，输出末尾附 `候选=[...]`，列出推断过程中采集到的其他文本，供人工核对。

### 状态标记

| 标记 | 含义 |
|---|---|
| `[不可见]` | 元素在页面中不可见（隐藏或被折叠） |
| `[禁用]` | 元素处于 `disabled` 状态 |
| `[只读]` | 元素处于 `readonly` 状态 |
| `[必填]` | 元素标记为必填 |

其中 `[禁用]` 仅表示**该站点当前不允许编辑此字段**（例如站点将该字段置于其他页面维护），不代表字段本身无需填写，程序仍会尝试写入。

## 已知问题与处理方式

### `ReferenceError: __name is not defined`

**现象**：`frame.evaluate()` 执行扫描函数时报此错误，整个 frame 被跳过，扫描结果为 0。

**原因**：使用 `tsx` 运行时，其内部 esbuild 启用了 `keepNames`，会为命名函数（含嵌套函数）注入 `__name()` 包装。Playwright 将函数序列化为字符串后在页面内执行，页面上下文不存在该辅助函数。

**处理**：更换运行方式为 Node 原生类型擦除（不注入任何辅助函数），业务代码未作改动。连带调整两处：

- `package.json` 中的脚本改为 `node src/*.ts`；
- 各源文件的运行时导入后缀由 `./types.js` 改为 `./types.ts`（Node 不做 `.js` 到 `.ts` 的重写；此前 `connect-browser.ts` 可运行仅因其对应导入为 `import type`，在编译期被擦除）。

### 进程执行完毕后不退出

**原因**：`connectOverCDP` 建立的 WebSocket 持续占用事件循环，而 `browser.close()` 不可调用，导致 `main` 结束后进程挂起。

**处理**：新增 `flushAndExit()` 显式退出，且依次冲刷 `stdout` 与 `stderr` 后再调用 `process.exit()`。仅冲刷 `stdout` 会导致在输出重定向至管道的场景下（如 `cmd 2>&1 | ...`）错误内容被截断。

### 自定义控件的占位文本被误判为字段标签

**现象**：美团页面上 9 个下拉字段的标签均被识别为「请选择」。

**原因**：标签推断在下拉组件内部即命中占位节点并直接返回，真实标签位于组件外层的表单项中，未被访问。

**处理**：新增三条规则：

1. 祖先链仍处于自定义组件内部时，跳过该层级；
2. 每层优先检查前置兄弟节点（招聘系统的真标签通常位于控件容器的前置兄弟位置）；
3. 建立占位词黑名单，并剥离标签文本前的「请选择 / 请输入」等提示前缀。

同时，读取标签文本前剔除嵌套控件内容，避免产生「手机号码\*86」这类粘连结果。

### `disabled` 被误用作过滤条件

**现象**：美团页面的手机号字段被跳过。

**原因**：该字段被站点置于账号设置页维护，当前页呈现为禁用。此属站点差异，而非字段属性。

**处理**：从匹配逻辑中移除 `disabled` 过滤，改为正常尝试写入；写入失败时捕获异常并输出说明性提示，而非输出 Playwright 原始错误信息。

> `readonly` 过滤予以保留：日期选择器等控件的输入框普遍为只读，对其执行写入无实际意义。

### 单选/复选的标签被识别为选项文字（京东站点）

**现象**：「是否最高学历」「是否双学位」等单选组被拆成多个字段，标签为「是」「否」。

**原因**：单选/复选的选项通常各自被 `<label>` 包裹，`label-wrap` 的优先级高于容器结构推断，选项文字先命中即返回；真实字段标签位于选项前方的容器结构中，未被访问。

**处理**：单选/复选控件的推断顺序调整为容器结构优先，`label[for]` 与包裹 `<label>` 降为回退；就近查找时跳过包含单选/复选控件的选项标签，避免把相邻选项的选项文字当作标签。

### div 模拟的下拉未被扫描（京东站点）

**现象**：「学习形式」「专业成绩排名」等下拉未出现在扫描结果中。

**原因**：此类控件由 div 模拟，不产生 `input` / `textarea` / `select` 节点，超出原扫描范围。

**处理**：新增自定义控件识别——按组件类名关键词查找「容器内不含原生控件」的自定义下拉，记为 `other/combobox`，仅作识别、不可自动填写；含原生控件的组件（如美团的 mtd-select）仍按原生控件报告，避免重复。

### 自定义控件排在末尾，输出顺序与页面不符（京东站点）

**现象**：15 个 div 模拟下拉集中输出在全部原生控件之后，与它们在页面上的实际位置不一致。

**原因**：原生控件与自定义控件分两轮采集，自定义控件直接追加到结果数组末尾，未参与排序。

**处理**：新增 `localIndex`（记录控件在原生控件中的序号，自定义控件为 -1）与并行节点数组，采集完成后按 `compareDocumentPosition` 合并排序，使输出顺序等于 DOM 顺序。

## 已知限制

1. **`combobox` 类控件无法自动填写**。此类控件需通过点选完成赋值，且多数受控组件在仅写入 DOM 值的情况下不会更新内部状态。本阶段仅做识别，不做处理。
2. **附件上传不支持**，对应 `file` 类型。
3. **多步骤表单不会自动翻页**，仅扫描当前步骤。
4. **控件定位依赖 DOM 顺序**。页面在扫描后若发生重渲染将导致定位失效；程序通过数量校验检出该情况并报错，不会写入错误控件。
5. **姓名字段匹配基于关键词评分**，无法穷举所有站点表述，适配新站点时可能需要扩充关键词或排除词。
6. **不保留跨运行状态**，每次运行均重新扫描页面。
7. **附件上传字段的标签可能取到所在区域名称**。京东站点上 4 个 `file` 控件均被标记为「基本信息」，即页面区域名，实际标签需人工核对。
8. **自定义控件识别基于类名关键词**，可能误报（把下拉菜单项识别为字段）或漏报（站点使用自定义类名时不识别）。

## 隐私与数据安全

- 扫描输出包含页面上的真实内容，可能涉及姓名、身份证号、手机号、邮箱等个人信息。**在截图、文档或对外分享时必须脱敏。**
- `.gitignore` 仅阻止文件入库，**无法约束终端输出与截图中的信息**，脱敏须由使用方完成。
- 测试 Chrome 的用户数据目录包含登录态，**禁止提交至版本库**（已在 `.gitignore` 中配置 `chrome-cdp-profile/`）。
- 本程序不读取、不写入、不上传任何本地文件；全部操作仅作用于当前页面的 DOM。
- 在真实简历页面上执行 `fill` 后，请通过站点的「取消」或手动编辑还原数据。部分站点为即时保存，写入会直接落库。

## 常见问题

**Q：`npm run connect` 提示无法连接到 9222。**

A：目标 Chrome 未以远程调试端口启动，或已存在另一实例占用同一用户数据目录。按「启动测试 Chrome」中的命令重新启动，并确认 `http://127.0.0.1:9222/json/version` 可返回 JSON。

**Q：`observe` 输出 0 个字段。**

A：多数情况是选中的标签页不是表单页。先执行 `npm run connect` 查看候选列表，再用序号指定目标页。

**Q：标签识别错误，例如多个字段显示同一标签。**

A：查看该行的 `labelSource` 与 `候选=[...]`。若为真标签出现在候选项中，说明推断优先级需调整；若未出现在候选项中，说明目标结构需增加向上遍历的层级。
